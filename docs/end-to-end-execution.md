## Stage 3: Image Build and Deployment

### 1. Multi-Stage Dockerfile Execution
[`Dockerfile`](file:///Users/nagarjuna_m/.gemini/antigravity-ide/scratch/interview-prep/Dockerfile) optimizes production build time and security:
- **Stage 1 (Builder):** Resolves dependencies offline via `mvn dependency:go-offline` (cached in Docker layer), then compiles and packages the fat JAR.
- **Stage 2 (Runtime):** Copies only `/app/target/*.jar` into an `eclipse-temurin:21-jre` minimal image. Creates and assigns an unprivileged system user:
  ```dockerfile
  RUN groupadd -r spring && useradd -r -g spring spring
  USER spring
  ```
- **Security:** Root filesystem access is disabled for runtime containers, mitigating container breakout vulnerabilities.

### 2. Local Deployment via Docker Compose
```bash
docker compose up -d --build
```
- Starts `interview-prep-service` mapped to host port `8081:8081`.
- Configures environment variable `SPRING_PROFILES_ACTIVE=docker`.

### 3. Kubernetes Deployment (Production Target)
Manifests located in [`infrastructure/kubernetes/`](file:///Users/nagarjuna_m/.gemini/antigravity-ide/scratch/interview-prep/infrastructure/kubernetes/):
- **RollingUpdate Strategy:** `maxSurge: 1`, `maxUnavailable: 0` ensures zero downtime.
- **Readiness Probe:** Queries `GET /api/v1/prepStart` before routing traffic through the Service.
- **Liveness Probe:** Restarts unhealthy pods if internal threads hang.

## Stage 4: Incoming Request Execution Trace

Tracing an incoming HTTP request end to end:

```http
POST /api/v1/employees HTTP/1.1
Host: localhost:8081
Content-Type: application/json

{
  "firstName": "Asha",
  "lastName": "Rao",
  "email": "asha.rao@example.com",
  "department": "ENGINEERING",
  "salary": 85000.00
}
```

```text
HTTP Request
    │
    ▼
1. Embedded Web Server (Apache Tomcat 10 / NIO Connector)
   Worker thread dispatched from ThreadPoolExecutor (default 200 threads).
    │
    ▼
2. Servlet Filters (Security, CORS, Logging, OpenTelemetry Tracing)
   Correlation ID injected into MDC (Mapped Diagnostic Context).
    │
    ▼
3. DispatcherServlet (Front Controller Pattern)
   Central coordinator parses the request and invokes HandlerMapping.
    │
    ▼
4. HandlerMapping & HandlerAdapter
   RequestMappingHandlerMapping resolves URL to EmployeeController#createEmployee.
    │
    ▼
5. Message Conversion & Validation
   - MappingJackson2HttpMessageConverter deserializes JSON into EmployeeRequest record.
   - ValidatorImpl evaluates Bean Validation annotations (@NotBlank, @Email, @PositiveOrZero).
   - If invalid: MethodArgumentNotValidException is thrown directly to GlobalExceptionHandler.
    │
    ▼
6. Controller Layer (EmployeeController)
   Invokes employeeService.createEmployee(request).
    │
    ▼
7. CGLIB Dynamic Proxy & Transaction Interceptor
   - Intercepts method call for @Transactional.
   - PlatformTransactionManager checks current context and opens a JDBC Connection from HikariCP.
   - autoCommit set to false.
    │
    ▼
8. Service Layer Business Logic (EmployeeServiceImpl)
   - Checks employeeRepository.existsByEmail("asha.rao@example.com").
   - If duplicate: throws DuplicateResourceException (rolls back transaction).
   - Maps DTO to new Employee entity.
    │
    ▼
9. Data Access & Persistence (EmployeeRepository / Hibernate)
   - EntityManager#persist() assigns entity to First-Level Persistence Context (Managed state).
   - @PrePersist sets createdAt and updatedAt timestamps.
   - Hibernate generates SQL: INSERT INTO employees (first_name, last_name, email, department, salary, created_at, updated_at) VALUES (?, ?, ?, ?, ?, ?, ?).
    │
    ▼
10. Database Execution (JDBC Driver / Database Engine)
    - PreparedStatement compiled and executed against database.
    - Identity sequence generates primary key id = 1.
    │
    ▼
11. Transaction Completion & Commit
    - Service method returns without exception.
    - TransactionInterceptor calls Connection#commit().
    - HikariCP returns connection to the connection pool.
    │
    ▼
12. Response Serialization & Return
    - Entity mapped to EmployeeResponse record.
    - Controller builds ResponseEntity.created(Location: /api/v1/employees/1).
    - Jackson serializes EmployeeResponse to JSON.
    - Tomcat writes HTTP 201 Created to socket output stream.
```

## Stage 6: Production Troubleshooting Runbooks

### 1. Application Startup Failure (Port Conflict)
- **Symptom:** `Web server failed to start. Port 8081 was already in use.`
- **Diagnostic Command:**
  ```bash
  # Check listening processes on macOS / Linux
  lsof -i :8081
  # View process details
  ps aux | grep java
  ```
- **Remediation:**
  - Safely terminate conflicting process: `kill -15 <PID>` (or `kill -9 <PID>` if unresponsive).
  - Alternatively, override port dynamically: `SERVER_PORT=8082 mvn spring-boot:run`.

### 2. Database Connection Exhaustion (HikariCP Pool Timeout)
- **Symptom:** `Connection is not available, request timed out after 30000ms.`
- **Diagnostic Command:**
  ```bash
  # Check active database connections in PostgreSQL
  SELECT count(*), state FROM pg_stat_activity GROUP BY state;
  # Identify long-running transactions
  SELECT pid, now() - xact_start AS duration, query FROM pg_stat_activity WHERE state != 'idle' ORDER BY duration DESC;
  ```
- **Likely Causes:**
  - Long-running unindexed queries holding connections.
  - Transactions performing external REST/network calls while holding DB connection (anti-pattern).
  - HikariCP pool size too small (`spring.datasource.hikari.maximum-pool-size`).
- **Remediation:**
  - Increase pool size according to PostgreSQL formula: `connections = ((core_count * 2) + effective_spindle_count)`.
  - Set `spring.datasource.hikari.leak-detection-threshold=2000` to log stack traces of unreturned connections.

### 3. High Latency & Slow Database Queries
- **Symptom:** API response times degrade from 15ms to 2500ms.
- **Diagnostic Command:**
  ```sql
  EXPLAIN ANALYZE SELECT * FROM employees WHERE email = 'asha.rao@example.com';
  ```
- **Likely Causes:** Sequential table scans (`Seq Scan`) instead of `Index Scan`.
- **Remediation:** Verify indexes exist on columns queried in WHERE / JOIN / ORDER BY clauses (`@Index(name = "idx_employee_email", columnList = "email")`).

### 4. Memory Pressure & OutOfMemoryError (Java Heap Space)
- **Symptom:** `java.lang.OutOfMemoryError: Java heap space`.
- **Diagnostic Command:**
  ```bash
  # Check live heap usage
  jcmd <PID> GC.heap_info
  # Generate live heap dump for inspection
  jcmd <PID> GC.dump /tmp/heapdump.hprof
  # Analyze dump with Eclipse Memory Analyzer (MAT) or JProfiler
  ```
- **Remediation:**
  - Check for unbounded in-memory collections, unclosed streams, or pagination queries fetching entire tables into memory without `Pageable`.
  - Configure JVM flags: `-XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/var/log/heapdump.hprof`.

### 5. Thread Pool Starvation / CPU Spikes
- **Symptom:** Server stops responding, CPU utilization hits 100%.
- **Diagnostic Command:**
  ```bash
  # Capture 3 successive thread dumps at 5-second intervals
  jcmd <PID> Thread.print > /tmp/threaddump_1.txt
  sleep 5
  jcmd <PID> Thread.print > /tmp/threaddump_2.txt
  ```
- **Likely Causes:**
  - Thread deadlock (look for `Found one Java-level deadlock` in dump output).
  - High contention on synchronized blocks.
  - Infinite loops or regex catastrophic backtracking.
